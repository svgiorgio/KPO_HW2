# Проект «ПОС»

Консольное приложение для учёта преподавательской оценки студентов, реализованное с применением DDD, слоистой архитектуры Ports & Adapters и паттернов GoF.

## 1. Архитектура (Ports & Adapters)

Выбрана архитектура **Ports & Adapters (Гексагональная)**. Зависимости направлены строго внутрь: `Infrastructure` -> `Application` -> `Domain`.

*   **`domain/` (Ядро)** — сущности, объекты-значения, инварианты, доменные сервисы и порты. Слой не зависит от фреймворков, базы данных или консоли.
*   **`application/` (Сценарии)** — Use Cases, которые оркестрируют вызовы домена и работу с портами.
*   **`infrastructure/` (Адаптеры)** — реализация портов, консольный интерфейс и DI-контейнер.

## 2. DDD

*   **Ubiquitous Language**: Студент, Критерий, Оценка, Итоговый балл.
*   **Entity**: `Student`, `Criterion`, `Evaluation`. Обладают уникальными идентификаторами, состояние может меняться.
*   **Value Object**: `Score`, `Weight`, `StudentId`, `CriterionId`. Неизменяемы. Пример: `Score` содержит логику проверки на отрицательное значение прямо в конструкторе.
*   **Инварианты**: 
    *   Балл не может быть отрицательным.
    *   Балл не может превышать максимальный балл критерия.
    *   Оценка не может быть выставлена по несуществующему критерию.
*   **Repository**: Интерфейсы хранилищ описаны в `domain/ports.py`, что позволяет легко заменить In-Memory хранение на БД без изменения ядра.
*   **Domain Service**: `GradeCalculator` в `domain/services.py`. Считает итог, так как это правило требует данных из разных сущностей и не принадлежит одной из них.

## 3. Паттерны GoF

В проекте применены три паттерна, по одному из каждой группы:

* **Фабрика** — `EvaluationFactory` в `domain/models.py`. Централизует создание `Evaluation` и проверяет инвариант: балл не может превышать `max_score` критерия.
* **Фасад** — `ConsoleUI` в `infrastructure/ui.py`. Скрывает инициализацию DI-контейнера и вызовы Use Cases за одним методом `run_demo`.
* **Стратегия** — `GradeStrategy` в `domain/services.py`. Позволяет менять алгоритм подсчета итога, не затрагивая `GradeCalculator`. Сейчас используется `WeightedSumStrategy`.

## 4. Роль ИИ
ИИ использовался как вспомогательный инструмент для генерации шаблонов классов и написания кода (DI-контейнер, консольный интерфейс). Архитектура, проектирование доменной модели, инварианты и паттерны спроектированы самостоятельно. Код проверен и покрыт тестами.

## Запуск и тестирование
